1. XML FUNDAMENTALS (Highest frequency — appears 20+ times)
─────────────────────────────────────────────────────────────────────────────
• XML was created by simplifying SGML
• W3C is responsible for specifying XML
• Well-formed XML MUST have: exactly ONE root element, all tags properly closed,
  case-sensitive tag names, attribute values in quotes
• Valid XML = well-formed + complies with a schema (XSD or DTD)
• A valid document is ALWAYS well-formed; a well-formed is NOT always valid
• XML element names: CANNOT start with a number, CAN include hyphens/underscores/periods,
  CAN include colons (when using namespaces)
• XML attributes: MUST have a value, can use single or double quotes, can be listed in any order
• XML can be: valid, well-formed (these are the only two states)
• XML namespaces: prevent naming conflicts between elements and attributes
• Purposes of XML: define structure of documents, define custom markup languages,
  transfer data between different applications and systems
• SVG files: use XML format, represent image data TEXTUALLY, are VECTOR graphics

2. XSD — XML SCHEMA DEFINITION (Highest frequency — 15+ questions)
─────────────────────────────────────────────────────────────────────────────
CRITICAL to memorize all restriction facets:

• xs:simpleType   → defines custom data type based on an EXISTING simple type
• xs:complexType  → defines elements with nested children OR attributes
• xs:restriction  → base element for restrictions — used INSIDE simpleType
• Inside xs:restriction, these elements restrict values:
    - xs:minLength / xs:maxLength   → restrict string length
    - xs:minInclusive / xs:maxInclusive → restrict numeric values
    - xs:enumeration                → restrict to list of allowed values
    - xs:pattern                    → restrict using regex pattern
• maxOccurs="unbounded" syntax:
    <xs:element name="item" type="xs:string" minOccurs="0" maxOccurs="unbounded"/>
• DTD = Document Type Definition: set of rules describing elements and content structure
• DocBook: for writing technical documentation in XML; latest version uses RelaxNG + XSD
• RelaxNG: schema language for XML, simpler than XSD for defining document structures
• XSD Design Patterns: goal = creating a consistent and maintainable structure for XML Schema

6. HTTP PROTOCOL AND REST API (10+ questions)
─────────────────────────────────────────────────────────────────────────────
• HTTP: protocol for transferring data between a client and a server
• HTTP methods that MANIPULATE data (unsafe): POST, PUT, DELETE (also PATCH)
• GET is safe (read-only)
• REST API verbs: POST, GET, PUT, DELETE, PATCH
• REST = Representational State Transfer
• REST principles: Cachability, Client-Server interface, Unified Interface, Statelessness
• HTTP Status Codes — MEMORIZE THESE:
    200 OK               → success
    201 Created          → resource created (after POST)
    204 No Content       → success but no body (after DELETE)
    500 Internal Server Error → server failure
• 2xx = success; 5xx = server error
• WebSockets advantage over HTTP: BIDIRECTIONAL (full-duplex) communication
  (HTTP is request-response only; WebSockets allow real-time two-way communication)

1. LEONTIEF INPUT-OUTPUT MODEL (Confirmed on exam — "complete the table" problem)
─────────────────────────────────────────────────────────────────────────────
STEP-BY-STEP PROCEDURE:

Step 1: Complete the table
  → Total Inputs ALWAYS = Total Outputs for each sector
  → Find the one missing value per row by using the equation

Step 2: Build the A matrix (coefficient matrix)
  → For each column: divide each cell by that column's TOTAL INPUT
  → A[i,j] = value[i,j] / TotalInput[j]

Step 3: Build the I matrix (identity matrix)
  → Always: diagonal = 1, everything else = 0
  → For 3 sectors: [[1,0,0],[0,1,0],[0,0,1]]

Step 4: Build (I - A) matrix
  → Subtract A from I cell by cell

Step 5a: If task gives NEW X (total production), find new Y (final demand):
  → new_Y = (I - A) * new_X

Step 5b: If task gives NEW Y (final demand), find new X (total production):
  → new_X = (I - A)^(-1) * new_Y
  → Must invert the (I-A) matrix first!

KEY FORMULA: x = (I - A)⁻¹ * y

2. LINEAR PROGRAMMING — SIMPLEX SENSITIVITY ANALYSIS (Confirmed on exam)
─────────────────────────────────────────────────────────────────────────────
The exam shows you a simplex sensitivity report and asks "what happens if X changes?"

RULES:
• If an objective function coefficient changes WITHIN its allowable range:
    → Basis stays the SAME, but the optimal Z VALUE changes
• If an RHS (right-hand side constraint) changes WITHIN its allowable range:
    → Solution values change BUT the basis stays the same
• If a change is OUTSIDE the allowable range:
    → THE BASIS CHANGES (new optimal solution structure)

EXAMPLE FROM SOURCE FILE:
  "Objective function coefficient was 220. Profit looks like it will be 250."
  → If allowable increase was 20 (so max allowed is 240), then 250 > 240
  → Answer: The BASIS WILL CHANGE

Excel Solver setup:
  → LHS formulas use: =SUMPRODUCT(variable_cells, coefficient_range)
  → Objective: maximize or minimize the SUMPRODUCT formula
  → Constraints: LHS <= RHS

─────────────────────────────────────────────────────────────────────────────
3. SIMULATION — MONTE CARLO (Theory questions)
─────────────────────────────────────────────────────────────────────────────
• Simulation = imitation of a real-world system to evaluate and improve performance
• Types of simulations (THREE axis classification):
    Static vs Dynamic:
      Static  = single point in time, no change over time
      Dynamic = models changes OVER TIME
    Stochastic vs Deterministic:
      Stochastic   = involves randomness; different result each run
      Deterministic = predictable; same inputs → same output always
    Discrete-event vs Continuous:
      Discrete-event = events occur at specific discrete points in time
      Continuous     = changes occur continuously over time

• Monte Carlo = STATIC + STOCHASTIC simulation
  → Uses large numbers of random numbers to simulate a system/problem
  → Classic example: estimating π by throwing random points in a square

─────────────────────────────────────────────────────────────────────────────
4. MARKOV CHAINS (Theory questions)
─────────────────────────────────────────────────────────────────────────────
• Markov chain = mathematical model where system moves between states
• The NEXT state depends ONLY on the CURRENT state (NOT past states)
• This is called: MEMORYLESSNESS (also called "Markov property")
• Also: HOMOGENEITY — transition probabilities don't change over time

Properties:
  1. Memorylessness: next state depends only on current state
  2. Homogeneity: transition probabilities are constant (don't change as chain progresses)

• A Markov chain has: a SET OF STATES and a TRANSITION MATRIX
• Transition matrix rows must sum to 1.0

Stationary distribution:
  π * P = π  AND  Σπᵢ = 1
  (Solve this system of equations to find long-run steady-state probabilities)

─────────────────────────────────────────────────────────────────────────────
5. SYSTEM THEORY AND THINKING (Theory questions)
─────────────────────────────────────────────────────────────────────────────
• System = a group of elements and the RELATIONS between those elements
• Complex system = multiple interacting elements where whole behavior CANNOT be
  explained only by individual parts

5 Components of a Complex System:
  1. Self-organization: organizes itself WITHOUT external control
  2. Emergence: whole behavior cannot be predicted from individual parts
  3. Nonlinearity: small change in one part → large effect on whole system
  4. Adaptation: changes behavior/structure in response to changing conditions
  5. Feedback loops: outputs feed back as inputs

System classification:
  Closed system = does NOT need to interact with environment (atoms, molecules)
  Open system   = MUST interact with environment to survive (people, ecosystems)

System THINKING:
  = analyzing complex systems as a WHOLE, not just individual parts
  = understanding how changes in ONE part cause changes in ANOTHER part

Soft Thinking vs Hard Thinking:
  SOFT (SSM)                      | HARD (HST)
  ─────────────────────────────── | ───────────────────────────────
  Oriented to LEARNING            | Oriented to GOAL SEEKING
  World is complex & problematic  | World has engineerable systems
  Models = intellectual constructs| Models = actual world models
  (epistemology-based)            | (ontology-based)
  Uses "issues" & "accommodations"| Uses "problems" & "solutions"
  ✓ Accessible to problem owners  | ✓ Allows use of powerful techniques
  ✗ No final answers              | ✗ Needs experts; ignores human aspects

Model types:
  Normative vs Descriptive: Normative = what SHOULD be done; Descriptive = what IS being done
  Static vs Dynamic: Static = one point in time; Dynamic = changes over time
  Deterministic vs Stochastic: Deterministic = all variables known; Stochastic = accounts for randomness

1. IP ADDRESSES AND NETWORKING FUNDAMENTALS (High frequency)
─────────────────────────────────────────────────────────────────────────────
• Regular IPs: assigned by your ISP, describe approximate location, limited supply
• Private IPs: can be used by multiple devices but only within the SAME isolated local network
• Private IPs allow: communication between devices on the SAME network
• Beyond the local network: requires NAT (Network Address Translation)
• NAT: converts private IP → public IP for communication outside the local network
• DNS = distributed database system
• DNS resolver: begins lookup chain from root servers
• Which is true for DNS: "DNS is a distributed database"
• Windows and GNU/Linux default diagnostic tools: traceroute (tracert on Windows) and ping

2. CLOUD COMPUTING (Written answer question — Essay expected)
─────────────────────────────────────────────────────────────────────────────
Template answer structure:
  "There is no cloud, it's just someone else's computer."
  Cloud = service providing convenient, redundant, and safe data storage to clients
  Three deployment types: Private cloud, Hybrid cloud, Public cloud
  Three service types:
    PaaS = Platform as a Service
    IaaS = Infrastructure as a Service
    SaaS = Software as a Service

GDPR-sensitive data → Private cloud
Web applications → Public cloud

─────────────────────────────────────────────────────────────────────────────
3. COOPERATIVE vs PRE-EMPTIVE MULTITASKING (Written answer question)
─────────────────────────────────────────────────────────────────────────────
Cooperative Multitasking (OLD method):
  → Apps managed their OWN resources
  → Each app released resources when done
  → Problem: faulty/badly written apps could crash the whole system
  → Historical (used in old Mac OS, Windows 3.x)

Pre-emptive Multitasking (MODERN method):
  → OS is in charge of allocating CPU time to applications
  → If app misbehaves, OS can forcibly SHUT IT DOWN and reallocate resources
  → Modern OS uses pre-emptive
  Timeline:
    → Unix: ALWAYS used pre-emptive from the beginning
    → Windows: started with Windows NT and Windows 95
    → Mac: started with Mac OS X (called OS X)

─────────────────────────────────────────────────────────────────────────────
4. TEXT/COMMAND LINE INTERFACE — CLI/TUI (Written answer question)
─────────────────────────────────────────────────────────────────────────────
What is TUI/CLI:
  → Text-based user interface, displays graphics in text mode
  → Also called: command line interface, shell

CLI Advantages:
  ✓ Faster for experts who know commands
  ✓ Does NOT require Windows (runs on boot or headless servers)
  ✓ Low RAM usage (text only)
  ✓ Runs on low-resolution screens
  ✓ Low CPU processing
  ✓ Remote access requires LOW BANDWIDTH (key exam point)
  ✓ User can perform ANY action that has a command

CLI Disadvantages:
  ✗ Must memorize command sequences
  ✗ Difficult for novices/beginners
  ✗ No autocomplete or suggestions
  ✗ Spelling errors restart the process
  ✗ High learning curve
  ✗ Unknown conventions (unusual compared to GUI)
  ✗ Eye strain from same color scheme

CLI is used today in: networking setup, server administration, DevOps, scripting
Examples: MS-DOS (Windows), bash/zsh (Linux/Mac), Windows PowerShell

─────────────────────────────────────────────────────────────────────────────
5. VIRTUAL MEMORY (Written answer question + multiple choice)
─────────────────────────────────────────────────────────────────────────────
• Virtual memory = memory management technique
• Uses HDD/SSD disk space to simulate additional RAM
• How: OS divides memory into PAGE FILES or SWAP FILES
• The OS copies pages from disk to RAM when needed
• Virtual addresses are then translated into real physical addresses
• KEY TERM when using virtual memory + HDD: "SWAPPING" (also "paging")
• Software responsible for virtual memory: THE OPERATING SYSTEM (e.g., Windows, Linux)
• Benefit: allows running larger programs or more programs than physical RAM allows
• Computers have FINITE RAM → virtual memory compensates

─────────────────────────────────────────────────────────────────────────────
6. WIRELESS NETWORKING (Written answer question)
─────────────────────────────────────────────────────────────────────────────
Advantages:
  ✓ Increased range with relatively easy installation
  ✓ No cables (cables are expensive and require maintenance)
  ✓ Faster to install than wired networks
  ✓ Cost-effective long-term (despite higher initial costs)
  ✓ Mobility and portability — enables portable devices
  ✓ Works in places cables cannot reach

Disadvantages:
  ✗ Security risks (poor encryption/password protection)
  ✗ SLOWER data transfer speeds than wired alternatives
  ✗ Signal degrades with distance from origin
  ✗ Prone to interference (especially in shared/free frequency bands)
  ✗ Limited bandwidth — cannot support video conferencing (VTC)
  ✗ Limited extensibility due to lack of wireless spectrum

─────────────────────────────────────────────────────────────────────────────
7. KEY QUICK-FIRE FACTS — Multiple Choice OS (Memorize these)
─────────────────────────────────────────────────────────────────────────────
• Linux = OS kernel (officially: "Linux is an OS kernel written from scratch")
• What function is NOT performed by OS: DEFRAGMENTATION
  (Defragmentation is a utility, not a core OS function — tricky!)
• BIOS software location: EEPROM / NAND flash memory (not RAM, not HDD)
• FAT16 max file system size: 4 GB
• OS resources controlled: CPU time + Operating memory (RAM)
• SSH vs Terminal: SSH uses an ENCRYPTED CHANNEL
• When PCs were introduced, users got: CPU power, operating memory, local storage
• Host-terminal model: used data networks for computing (terminals connected to mainframes)
• What creates/builds an OS: C, C++, C#, assembly language
• Defragmentation is NOT an OS function → it's a disk utility (often external)

─────────────────────────────────────────────────────────────────────────────
8. INTELLECTUAL PROPERTY — ESSAY TOPIC (Ozturk paper)
─────────────────────────────────────────────────────────────────────────────
Key arguments FOR intellectual property:
  → Provides incentive to invest time/money in new ideas
  → Rewards creativity and innovation
  → Protects ideas from being stolen without compensation
  → Without IP protection, people lose incentive to innovate

Key arguments AGAINST intellectual property:
  → Can create monopolies and STIFLE competition
  → Leads to higher prices for consumers
  → Reduced access to products/services
  → Large companies can use IP to prevent smaller companies from competing

Historical context:
  → Magna Carta (1215), US Declaration of Independence (1776),
    French Declaration (1789), Universal Declaration of Human Rights (1948)
  → All recognize property rights in some form

Balance: each society must decide the right balance between incentives and access.

❌ "Defragmentation is an OS function" → WRONG. It is a utility, not core OS.
❌ "DSS replaces managers" → WRONG. DSS SUPPORTS (not replaces) managers.
❌ "Competitive Intelligence = espionage" → WRONG. CI uses only PUBLIC/LEGAL sources.
❌ "Cooperative multitasking = modern" → WRONG. Pre-emptive is the modern standard.
❌ "A well-formed XML document is always valid" → WRONG. Valid = well-formed + schema-compliant.
❌ "JSON Schema maxLength restricts array" → WRONG. maxLength restricts STRINGS; use maxItems for arrays.
❌ "SSH is the same as a terminal connection" → WRONG. SSH uses ENCRYPTED channel.
❌ "ERP is more general than IS" → WRONG. IS is MORE GENERAL than ERP.
❌ "Soft systems thinking produces final answers" → WRONG. SSM accepts that questioning never stops.
