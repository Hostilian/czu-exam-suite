🗄️ Data Warehouse
Most heavily tested topic (8+ questions) — SINV, OLTP vs OLAP, ETL, schemas
📦
DW SINV Properties — Core Exam Topic
Remember "Subject·Integrated·Non-volatile·Time-variant"
S
Subject-Oriented
Organized around subjects (sales, products, customers) — NOT around applications or processes
I
Integrated
Combines data from multiple sources consistently — one unified format/naming
N
Non-Volatile
Data is stable and historical — NOT updated/deleted like operational OLTP data
V
Time-Variant
Connected with time — every record has a timestamp; tracks historical changes over time
DW purpose = STRATEGIC ANALYSIS and decision-making. NOT daily operations!
⚡
OLTP vs OLAP
Fundamental IS distinction
OLTP — Online Transaction Processing
OLAP — Online Analytical Processing
Operational (day-to-day)
INSERT, UPDATE, DELETE
Real-time, high volume
Used by: TPS
Example: ATM, POS system
Many small transactions
Current data only
Analytical (reporting/decisions)
SELECT, aggregate queries
Batch processing, historical
Used by: DW, BI tools
Example: Sales reports, KPIs
Few large complex queries
Historical + current data
🔄
ETL Process & DW Schemas
Extract: Pull data from source systems (CRM, ERP, CSV files)
Transform: Clean, standardize, aggregate (fix formats, remove duplicates)
Load: Write transformed data into the Data Warehouse
Star Schema
One central fact table surrounded by dimension tables. Simple, fast queries. Denormalized.
Snowflake Schema
Fact table + dimension tables + sub-dimensions. Normalized, saves space but slower.
Data Mart: A subset of DW focused on one department (Sales DW → Sales Data Mart)
⛏️
Data Mining & Big Data
Data Mining: Discovering hidden patterns and relationships in large datasets
Classification: Assigning data to categories (spam/not spam)
Clustering: Grouping similar data without predefined labels
Association: Finding co-occurrence rules (beer → diapers)
Big Data 3Vs: Volume, Velocity, Variety
Modern IS technologies: Cloud, Virtualization, Big Data, AI, Security
🔷 ERP Systems & SAP
SAP organizational levels, modules, T-codes, P2P/O2C flows, SAP HANA
🏢
ERP Overview
Enterprise Resource Planning
Definition: Integrated software system managing all core business processes
Main goal: Support decision-making process and centralize business data
Main advantage: Centralized data and real-time visibility across all departments
Main disadvantage: HIGH COSTS + vendor lock-in
Vendor lock-in: Company becomes dependent on a single vendor (hard/expensive to switch)
Leaders: SAP, Oracle, Microsoft
IS is MORE GENERAL than ERP — ERP is a specific TYPE of IS!

⚡
SAP HANA
High-performance Analytic Appliance
Type: In-memory database — all data stored in RAM, not on disk
Why faster: RAM access (nanoseconds) vs disk access (milliseconds) = 1000× faster
Enables: Real-time analytics on live transactional data (no separate DW needed)
S/4HANA: Next-gen ERP built exclusively on SAP HANA
SAP HANA = in-memory — data in RAM! NOT a disk-based traditional database.
📋 IS Theory & Decision Systems
DSS, decision types, AI/ML, BI, BPM, competitive intelligence, SDLC
🧠
Decision Support System (DSS)
7 questions on exam — know all of it
Definition: Interactive computer-based system that supports decision-making
Transforms: raw data → useful information
Supports: Strategic AND tactical decisions (not just one)
Role: Should SUPPORT managers, NOT replace them
Computers good at: Processing large amounts of data quickly
Humans good at: Flexibility, intuition, adaptation, contextual judgment
3 Decision Types:
Structured — procedure CAN be specified in advance
Example: payroll calculation, reorder quantity
Unstructured — procedure CANNOT be specified in advance
Example: CEO strategy, hiring a new executive
Semi-structured — SOME procedures can be specified, but NOT enough for a definite decision
Example: investment portfolio, product launch
🤖
AI, ML, Deep Learning
7 questions on exam
AI areas: NLP, Machine Learning, Computer Vision, Deep Learning
NLP: Natural Language Processing — human language understanding by machines
Machine Learning: Learning patterns from data without being explicitly programmed
Computer Vision: Interpreting visual/image data (self-driving cars, face recognition)
Deep Learning: Closely connected to multi-layer neural networks
Neural network: Inspired by human brain structure
Deep Learning = multi-layer neural networks — layers are the key differentiator from basic ML!
📈
BI & BPM
BI (Business Intelligence): Analyzes data and creates business insight for better decisions
BPM (Business Performance Management): BI + Planning
KPI (Key Performance Indicator): Measurable value showing how effectively goals are achieved
Dashboard: Visual display of important business information (KPIs, charts)
BPR (Business Process Reengineering): Radical redesign of business processes for dramatic improvement
🔍
Competitive Intelligence (CI)
Definition: Legal and ethical gathering of information about competitors
Purpose: Improving understanding of competitive environment
Sources: PUBLIC sources — press releases, reports, news, filings
NOT CI: Hacking, bribery, corporate espionage — those are illegal!
CI = LEGAL and ethical. Uses ONLY public information. NOT espionage!

☁️ Cloud & IS Security
SaaS/PaaS/IaaS, CIA Triad, ACID properties, authentication, GDPR
☁️
Cloud Service Models
SaaS / PaaS / IaaS — know who manages what
SaaS — Software as a Service
Provider manages everything including the application. You just use it.
Examples: Gmail, Salesforce, Microsoft 365, SAP ByDesign
PaaS — Platform as a Service = IaaS + OS + App Platform
Provider manages infrastructure + OS + runtime. You manage application code.
Examples: Heroku, Google App Engine, Azure App Service
IaaS — Infrastructure as a Service
Provider manages hardware/network only. You manage OS, middleware, and apps.
Examples: AWS EC2, Azure VMs, Google Compute Engine
PaaS = IaaS + OS + Application Platform (runtime)
Cloud deployment: Public cloud · Private cloud (GDPR data) · Hybrid cloud
🔒
CIA Security Triad
Core IS Security framework
C
Confidentiality
Only authorized users can access data. Encryption, passwords, MFA.
I
Integrity
Data is accurate and has not been tampered with. Checksums, digital signatures.
A
Availability
Systems and data are accessible when needed. Backups, redundancy, uptime.
🔬
ACID Database Properties
A — Atomicity: All or nothing — entire transaction completes or fully rolls back
C — Consistency: Transaction brings DB from one valid state to another
I — Isolation: Concurrent transactions don't interfere with each other
D — Durability: Committed transactions survive system failures (written to disk)
Example: Bank transfer: debit account A AND credit account B. If system crashes mid-way, Atomicity ensures both or neither happen.
🛡️
Authentication & Encryption
Authentication: Verifying WHO you are (login, password)
Authorization: Verifying WHAT you can do (access rights, roles)
MFA: Multi-Factor Authentication — something you know + have + are
Symmetric encryption: Same key for encrypt & decrypt (fast, AES)
Asymmetric encryption: Public key (encrypt) + Private key (decrypt) — RSA, TLS
GDPR-sensitive data: Must stay in private cloud (EU data protection law)
Backup types: Full (everything) · Incremental (changes since last backup) · Differential (changes since last FULL)
