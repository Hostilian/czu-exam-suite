OS Core Facts
OS controls: CPU time + Operating memory (RAM)
NOT OS function: Defragmentation (disk utility)
OS built with: C, C++, C#, Assembly language
Linux: Open-source OS kernel by Torvalds, 1991, NOT from Unix
BIOS: In EEPROM or NAND flash memory on motherboard
FAT16 max: 4 GB (16-bit cluster addressing limit)
💾
Virtual Memory
Definition: OS uses HDD/SSD space to simulate extra RAM
Windows: page files | Linux: swap files
Recommended ratio: 3:1 (swap space : RAM)
Managed by: OS kernel — not hardware
Swapping: Moving ENTIRE process to disk
Paging: Moving fixed-size blocks (pages) RAM ↔ disk
Exam Q: "Which software manages virtual memory?" → The OS (kernel)
⚡
Multitasking Types
Cooperative
Pre-emptive ✓ Modern
Apps manage own resources. Voluntarily yield CPU. Bad app = whole system crashes. Used in early Windows/Mac.
OS forcibly controls CPU time. Can kill any misbehaving app. Used in modern Linux, Windows NT+, macOS X+.
🌐
Network Quick Facts
DNS: Distributed database. Reads names right-to-left (root first)
SSH port: 22 — encrypted. Telnet port 23 — NOT encrypted
TCP: connection-oriented, reliable | UDP: connectionless, fast
NAT: Translates private IPs → public IP at router
DHCP: Auto-assigns IP addresses (ports 67 server, 68 client)

What is an OS?
Core functions and components
Purpose 1: Manage system resources — CPU time + RAM
Purpose 2: Bridge between user/apps and hardware
5 OS Components:
1. Kernel — links apps to hardware
2. File System — data storage on disk (FAT16, NTFS, ext4)
3. Programming Language — C, C++, Assembly
4. User Interface — GUI or CLI
5. API — communication between programs
NOT done by OS: Defragmentation
💾
Virtual Memory — Deep Dive
Exam essay topic — know this cold
Definition: OS uses HDD/SSD as extension of RAM when RAM is full
Mechanism: Data pages moved between RAM and disk (swap)
Windows: pagefile.sys | Linux: swap partition
Recommended ratio: 3:1 (swap : RAM) — e.g. 8GB RAM → 24GB swap max
Who manages it: The OS kernel — NOT hardware
Swapping: Move entire process to disk
Paging: Move fixed-size pages (blocks) RAM ↔ disk
Pro: Run larger programs / more programs simultaneously without buying more RAM
Con: Much slower than real RAM — excessive use causes thrashing
⚡
Multitasking Types
Cooperative
Preemptive ✓ Modern
Apps yield CPU voluntarily.
Risk: buggy app monopolizes CPU → crash.
Used: early Mac, Windows 3.x
OS forces CPU reallocation.
Can kill/pause any app. No single point of failure.
Used: Windows NT+, Linux, macOS X+
Exam: Modern OSes use preemptive multitasking

Batch Processing
Computational model — exam essay topic
Definition: Jobs collected into batches, processed one-by-one on a mainframe without user interaction
Key feature: Offline processing — no real-time user involvement
✅ Advantages:
• No user interaction needed during run
• Effective use of physical resources
• Good for repetitive large-scale tasks
• Can run overnight/off-peak
❌ Disadvantages:
• No real-time feedback
• Errors discovered late (after whole batch)
• Operators need special training
• Inconvenient for users (long wait)

TCP vs UDP
TCP 🤝 Reliable
UDP ⚡ Fast
• Connection-oriented (3-way handshake)
• Guaranteed delivery
• Error checking + retransmission
• Ordered delivery
• Used: HTTP, FTP, SSH, SMTP
• Connectionless
• No guarantee of delivery
• Minimal error checking
• Out-of-order possible
• Used: DNS, DHCP, VoIP, video streaming

DNS — Domain Name System
DNS is a distributed database — not a central server
Resolvers read domain names from right to left (root → TLD → domain)
Example: www.google.com → reads: com → google → www
DNS port: 53 (both TCP and UDP)
DNS uses UDP for normal queries (fast), TCP for zone transfers (large data)
DNS resolvers begin reading names from the END (right side) — root-first!
