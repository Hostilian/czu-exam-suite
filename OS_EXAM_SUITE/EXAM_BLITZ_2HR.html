OS Core Facts
OS controls: CPU time + Operating memory (RAM)
NOT OS function: Defragmentation (disk utility)
OS built with: C, C++, C#, Assembly language
Linux: Open-source OS kernel by Torvalds, 1991, NOT from Unix
BIOS: In EEPROM or NAND flash memory on motherboard
FAT16 max: 4 GB (16-bit cluster addressing limit)
💾
Virtual Memory
Definition: OS uses HDD/SSD space to simulate extra RAM
Windows: page files | Linux: swap files
Recommended ratio: 3:1 (swap space : RAM)
Managed by: OS kernel — not hardware
Swapping: Moving ENTIRE process to disk
Paging: Moving fixed-size blocks (pages) RAM ↔ disk
Exam Q: "Which software manages virtual memory?" → The OS (kernel)

Multitasking Types
Cooperative
Pre-emptive ✓ Modern
Apps manage own resources. Voluntarily yield CPU. Bad app = whole system crashes.
OS forcibly controls CPU time. Can kill any misbehaving app and reallocate resources.
Adoption: Unix = always. Windows = NT/95. Mac = OS X.

What Makes an OS? (5 Components, 2 Purposes)
5 KEY COMPONENTS
Kernel — links apps to hardware (essential)
File System — manages data storage on LTSDs
Programming Language — C, C++, C#, Assembly
User Interface — GUI or CLI
API — App Program Interface, inter-program communication
2 MAIN PURPOSES
Resource management: CPU time + Operating memory (RAM)
Bridge: between user/applications and hardware
WHAT OS DOES NOT DO
Defragmentation is a disk utility tool — NOT an OS function!
COMPUTING MODELS (HISTORY)
Batch processing: Jobs queued, no user interaction, mainframe runs one-by-one. Key = offline processing
Host-terminal: Central mainframe processes everything; dumb terminals only carry I/O. First model using networks!
PC model: Each user gets own CPU, RAM, local storage
Client-server (3-layer): Universal client = web browser (WWW)
💾
Virtual Memory — Deep Dive
OS uses HDD/SSD disk space to extend available RAM beyond physical limit
Divided into page files (Windows) or swap files (Linux)
Inactive ("cold") pages moved to disk; needed pages loaded back to RAM
Managed by: OS kernel — translates virtual → physical addresses
Swapping: entire process moved to disk (slower)
Paging: fixed-size blocks (pages) moved between RAM ↔ disk
Recommended ratio: 3:1 — swap space should be 3× the physical RAM
Exam Q: "Which software manages virtual memory?" → The OS / OS kernel
Exam Q: "Mechanism allowing HDD data accessible by CPU?" → Swapping
🔄
Deadlock — 4 Conditions
ALL FOUR must hold simultaneously for deadlock to occur
1. Mutual Exclusion — resource used by one process at a time only
2. Hold and Wait — process holds resource AND waits for more
3. No Preemption — resource can't be forcibly taken from a process
4. Circular Wait — chain of processes each waiting for the next
Deadlock Handling:
Prevention: Eliminate ≥1 of the 4 conditions
Avoidance: Banker's Algorithm — check for safe state before granting
Detection + Recovery: Allow deadlock, detect it, then recover

CPU Scheduling Algorithms
FCFS: First Come First Served — simple, non-preemptive, can cause convoy effect
SJF: Shortest Job First — optimal average waiting time, but can starve long processes
Round Robin: Each process gets quantum Q time. Fair. Context switch overhead.
Priority: Highest priority first. Starvation risk → solved by Aging
Formulas: Waiting Time = Start − Arrival | Turnaround = Finish − Arrival
Throughput: processes completed per unit time | Response Time: time from submission to first response

What is a Server?
A server is a role a device takes to provide services to end users — NOT necessarily a dedicated physical machine
Typically assigned to powerful mainframes due to high request volume and OS/hardware limits
Output stored on dedicated storage arrays; runs many calculations
Common misconception: "a server = powerful dedicated computer" — it's just a role!
Types of servers: mail, proxy, application, virtual, blade, policy, file server

Process vs Thread: Process = own memory space. Thread = lightweight unit within process, shares memory.
📄
Page Replacement Algorithms
FIFO: Replace the page that has been in memory the longest
LRU: Replace the Least Recently Used page
Optimal: Replace page that won't be used for the longest time (theoretical)
Belady's Anomaly: Adding MORE frames can cause MORE page faults in FIFO (counter-intuitive!). Does NOT happen in LRU.
Page Fault: Required page is NOT in memory → must load from disk (expensive operation)

Subnetting Cheat Sheet
Network Address: IP AND Mask (all host bits = 0)
Broadcast: Network address + all host bits set to 1
Usable Hosts: 2^(host bits) − 2
First Host: Network address + 1
Last Host: Broadcast address − 1
Private IP Ranges:
Class A 10.0.0.0/8
Class B 172.16.0.0/12
Class C 192.168.0.0/16
Powers of 2:
2⁸=256
2⁷=128
2⁶=64
2⁵=32
2⁴=16
2³=8
2²=4
2¹=2
Example: 192.168.1.0/24 → Mask: 255.255.255.0 | Hosts: 2⁸−2 = 254 | Network: 192.168.1.0 | Broadcast: 192.168.1.255

TCP vs UDP
TCP
UDP
Connection-oriented (3-way handshake: SYN→SYN-ACK→ACK)
Connectionless — fire and forget, no setup

Network Devices by OSI Layer
1Hub — broadcasts to ALL ports, no intelligence, creates collisions
2Switch — uses MAC address table, sends to specific port only
3Router — IP routing, connects different networks, NAT
3+Firewall — packet filtering, stateful inspection, ACLs
ARP: Address Resolution Protocol — maps IP address → MAC address within LAN
NAT: Network Address Translation — private IP → public IP at router boundary
Default Gateway: Router IP address that handles traffic destined outside local network

🐧 Linux CLI Reference
Essential commands — search below, learn the most common ones first
🔐
chmod — Permission Numbers
7 = rwx (4+2+1)
6 = rw- (4+2)
5 = r-x (4+1)
4 = r-- (4)
chmod 755 file → owner: rwx, group: r-x, others: r-x (executable)
chmod 644 file → owner: rw-, group: r--, others: r-- (web files)
chmod +x file → add execute permission for everyone
Format: User | Group | Others — each digit is sum of: r=4, w=2, x=1

PID 1: init/systemd — the first process, parent of all others
