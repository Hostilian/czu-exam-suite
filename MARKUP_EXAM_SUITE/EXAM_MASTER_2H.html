HTML5 Semantics HTML

Core Definitions

  • <article>: Self-contained, independent, reusable content (e.g., blog post).
  • <section>: A thematic grouping of content, usually with a heading.
  • <aside>: Content indirectly related to the main content (e.g., sidebar).
  • <main>: Key content of the body. Must be unique (only one per page).
  • <figure> / <figcaption>: Self-contained flow content (image/code) with a caption.

Display & Validation

  • Block vs Inline: <div> / <p> are block; <span> / <a> are inline.
  • Inputs: required, placeholder, pattern (defines a regex to validate).
⚠️ EXAM TRAP: Never nest a <main> element inside <header>, <footer>, <nav>, or <aside>. A <section> should always contain a heading (h1-h6).
CSS Specificity & Selectors CSS

Specificity Vector Formula

(Inline, ID, Class/Attr/Pseudo, Element)
  • Inline Style (e.g., style="..."): 1, 0, 0, 0.
  • ID Selector (e.g., #header): 0, 1, 0, 0.
  • Class / Attribute / Pseudo-class (e.g., .btn, [type], :hover): 0, 0, 1, 0.
  • Element / Pseudo-element (e.g., h1, ::before): 0, 0, 0, 1.
  • Universal Selector (*) / Combinators (>, +, ~): 0, 0, 0, 0.

Special Rules

  • :not() / :is() / :has(): no specificity themselves; their arguments do.
  • !important: Overrides everything regardless of specificity vector.
⚠️ EXAM TRAP: If two selectors have equal specificity, the one declared last in the stylesheet wins. Class selectors always beat element selectors (e.g., .title specificity is 0,0,1,0; body h1 is only 0,0,0,2).
XML Basics & Namespaces XML

Syntax Guidelines

  • Case Sensitivity: Tags and attributes are case-sensitive.
  • Root element: Must have exactly one root element.
  • All tags must close (or use self-closing <tag />).
  • Attributes: Must be quoted (single or double).
  • Characters to escape: < as &lt; and & as &amp;.

Namespaces

  • Purpose: Avoid tag naming conflicts using unique URIs.
  • Syntax: xmlns:prefix="URI". Default namespace: xmlns="URI".
⚠️ EXAM TRAP: The XML declaration <?xml version="1.0" ... ?> must be on the very first line, with no preceding spaces or blank lines. Namespace URIs do NOT need to be resolvable or exist online; they are just unique identifier strings.
XML Schema (XSD) XSD

Type Classification

  • xs:simpleType: Can contain only text. No child elements, no attributes.
  • xs:complexType: Can contain child elements and/or attributes.

Compositors & Occurrences

  • xs:sequence: Children must appear in the exact order declared.
  • xs:all: Children can appear in any order, but max occurrence is 1.
  • xs:choice: Allows only one child element to appear.
  • Occurrences: Default minOccurs / maxOccurs is 1. For infinite occurrences, use unbounded.
⚠️ EXAM TRAP: Attributes in a xs:complexType must always be declared after the compositor (sequence/all/choice) and are always simple types. Set elementFormDefault="qualified" so elements are bound to targetNamespace.
XPath & XQuery XPath

XPath Shortcuts & Axes

  • /: Root node or direct child.
  • //: Descendant or self (search anywhere).
  • @: Selects attributes (e.g., //@id).
  • . / ..: Selects current node / parent node.
  • *: Wildcard, matches any element.
  • Functions: count(), sum(), contains(), normalize-space().

XQuery FLWOR Expression Mnemonic

For, Let, Where, Order by, Return
⚠️ EXAM TRAP: XPath node indices are 1-indexed, not 0-indexed. E.g., /root/item[1] selects the first item. Predicate filters like /item[@price > 10] return elements with that attribute value.
XSLT Transformations XSLT

Basic Core Elements

  • Root: <xsl:stylesheet> or <xsl:transform> with namespace xmlns:xsl="http://www.w3.org/1999/XSL/Transform".
  • Template rule: <xsl:template match="..."> (match root: match="/").
  • Apply templates: <xsl:apply-templates select="..." /> processes child rules.
  • Output element: <xsl:value-of select="..." /> outputs text value of matching node.
  • Loop: <xsl:for-each select="..."> loops over nodes.

Special Features

  • Conditional: <xsl:if test="..."> or <xsl:choose> / <xsl:when>.
  • Attribute Value Templates: Use curly braces {} inside attribute values (e.g. href="{$url}").
⚠️ EXAM TRAP: If no template matches a node, XSLT has a built-in default rule that recursively processes children and writes out text nodes. Always match nodes correctly to prevent unwanted concatenated text output.
JSON & Schema JSON

JSON Data Types & Syntax

  • Allowed types: String, Number, Object, Array, Boolean, Null (no Date, Functions, undefined).
  • Keys: Must always be double-quoted strings (single quotes are syntax error).
  • Commas: Trailing commas are strictly forbidden in arrays/objects.

JSON Schema Keywords

  • Structure: type, properties, additionalProperties (boolean).
  • Mandatory fields: required (takes an array of strings).
  • Validation: minimum / maximum (numbers), pattern (string regex).
⚠️ EXAM TRAP: Comments (e.g. // or /* */) are not allowed in standard JSON. In JSON Schema, required is an array at the object level, NOT a property attribute (unlike XSD).
HTTP & REST APIs HTTP

Methods (Verbs) Properties

  • GET: Retrieve data. Safe and idempotent.
  • POST: Create resource. Neither safe nor idempotent.
  • PUT: Replace resource. Idempotent but not safe.
  • PATCH: Partial update. Neither safe nor idempotent (normally).
  • DELETE: Delete resource. Idempotent but not safe.

HTTP Status Codes

  • 1xx: Informational | 2xx: Success (e.g. 201 Created).
  • 3xx: Redirect | 4xx: Client Error (e.g. 401 Unauthorized, 403 Forbidden).
  • 5xx: Server Error (e.g. 500 Internal Server Error).
⚠️ EXAM TRAP: Safe methods cannot change server state. Idempotency means multiple identical requests have the same effect as a single request. 401 means unauthenticated, while 403 means authenticated but unauthorized (insufficient permission).
CSV Standard (RFC 4180) CSV

RFC 4180 Rules

  • Delimiter: Standard is comma (,), but local formats often use semicolon (;).
  • Escaping: Fields containing commas, newlines, or quotes must be enclosed in double quotes.
  • Quotes inside: Escaped by preceding with another double quote (e.g., "").
  • Line break: Must use CRLF ( ).
⚠️ EXAM TRAP: CSV has no official metadata mechanism to define column types. Empty lines at the end of the file can cause parser issues. CSV does not natively support nested or hierarchical structures (unlike XML/JSON).
